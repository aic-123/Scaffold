# 验证钩子接口契约（通用规格）

本文件定义**验证方**如何与本工具对接。它是一份接口规格，**不绑定任何具体服务**——
没有 URL、没有厂商名、没有 SDK。谁都可以实现，谁都可以不实现。

---

## 一句话前提

> 本工具**完整可用，不需要任何外部服务**。`evidence_status` 只是一个留给你自己或其他验证方的空位。
> 不接任何验证方，工具照常工作。

这句话是这份契约的第一条，也是最重要的一条。下面四个环节里，③ 和 ④ 是**可选的**。
只做 ① 和 ②，你已经有了一套能用的知识结构工具，只是所有节点的状态都停在 `未验证`。

---

## 四环节

| 环节 | 输入 | 输出 | 谁做 |
|---|---|---|---|
| ① 待填清单 | 空节点 + 上下文字段 | 待办列表 | 开源层 |
| ② 提交填充 | 内容 + 出处 + `filled_by` | 节点内容 | 用户 / 任何填充器 |
| ③ 请求验证 | 节点内容 + 出处 | 审计结论（状态 + 样本与口径） | **外部验证方** |
| ④ 状态授予 | 审计结论 | `evidence_status` 升级 | **只有验证方有权写该字段** |

### ① 待填清单（开源层）

从结构生成"还欠什么"，不生成"该填什么"。

- 输入：`cues` 为空、`source.ref` 为空、`notes: 待填` 的节点，连同它们的 `type`、`scope`、`relations`
- 输出：一个待办列表。**只列缺口，不给答案**，也不按任何权威度排序
- **已实现**：`python validator/validate.py ./samples --todo`
  - 列出每个节点的缺口项，以及它已经挂上的关系（`relations`）
  - 排序键只有**文件路径**，不含来源、不含 `kind`、不含任何权威度
  - 会明确说明"**列出缺口不等于出错**"——「未验证 + 无出处」是合法状态，列在这里只因为它还欠着
  - 退出码恒为 `0`：缺口不是错误，所以不该让 CI 变红

### ② 提交填充（用户 / 任何填充器）

- 输入：写好的内容、`source.ref`、`source.kind`、`filled_by`
- 输出：一个符合 `schema/node.schema.yaml` 的节点文件
- 硬约束：`filled_by` 必须如实。人写的写 `人`，模型写的写 `模型(vX)`。
  **示例数据必须自曝身份**，见 `samples/` 里所有节点的 `filled_by: 模型(示例数据)`
- 取值本身**不设限制**（见 `SPEC.md`）：上面两种只是本仓库的约定，不是白名单。
  下游接自己的填充器时，可自定义取值并在自己的校验里加约束——**唯一不能省的是"留痕"本身**
- **一个例外：`未填充`**。它不是署名方式，是"这个节点还没人填过"这个事实断言。
  因此声明了它的节点里不能有任何内容，否则校验器报 R8。
  一个填充器若手里有内容，就不能写 `未填充`——那等于填了不留痕
- 填充器**无权**写 `已验证`。校验器会在 R7 拦下

### ③ 请求验证（外部验证方）

- 输入：节点内容 + 出处
- 输出：审计结论 = `evidence_status` + **样本与口径**
- 「样本与口径」是这一环的全部价值所在：不是一句"我验证过了"，而是
  **"我拿什么样本、按什么口径验的"**。没有这一项的审计结论，不比 `未验证` 更有信息量
- 用户可写的五个状态里，`已确立` / `假说` / `有争议` / `已淘汰` 描述的是**知识本身的性质**，
  由 ② 环节的人如实填写即可，不需要 ③
- 只有 `已验证` 必须走 ③——因为它说的不是知识，是**"有人验过了"**

### ④ 状态授予（只有验证方）

- 输入：③ 的审计结论
- 输出：`evidence_status` 升级为 `已验证`
- **只有验证方有权写这个字段。** 这是整个契约里唯一的权限声明

---

## 落地方式（两种，都合法）

**A. 不接验证方。** 不做 ③④。所有节点停在 `未验证`。
`python validator/validate.py ./samples` 照常工作，`--allow-verified` 永远不用打开。
这是默认形态，也是本 demo 的形态。

**B. 接一个验证方。** 验证方把授予结果写进一个**独立的输出目录**，
校验该目录时加 `--allow-verified`：

```
python validator/validate.py ./verified-out --allow-verified
```

两种内容的物理隔离是这个开关的**唯一**授权依据：

- 用户手写目录 / 样本目录 → **不加**该开关
- 验证方输出目录 → 加

在自己的手写目录上打开这个开关，等于关掉 R7。那不只是绕过一条规则，
是把"这个字段不能自己填"这条立项根基拿掉了。

---

## 本仓库不做的事

- 不实现 ③④ 的任何具体形态
- 不提供任何验证方名单、评分、可信度分级
- 不做联网、不做回调、不做轮询
- 不规定审计结论的文件格式——那是验证方自己的事
